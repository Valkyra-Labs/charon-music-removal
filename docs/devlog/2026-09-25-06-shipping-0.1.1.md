# 06. Shipping 0.1.1

2026-09-25.

## What was done

- CI: a GitHub Actions matrix (Linux default, no-default-features,
  realtime; macOS all features), MSRV 1.89 checked with `--locked`,
  docs build, and a weekly job that runs the real model.
- `Cargo.lock` committed: `ort` is a release candidate whose API
  changes between candidates, so the lockfile is part of the build.
- Public documents rewritten to contain only what a user needs;
  internal records kept outside the repository.
- 0.1.1 published to crates.io; 0.1.0 yanked (it did not build).

## What went wrong

- CI failed on clippy only: GitHub's toolchain (1.98) was newer than
  the local one and had a new lint. Fixed with `as_chunks`.
- `cargo publish` first failed with what looked like a CDN error (HTTP
  503 over HTTP/2); the underlying response was a 403 from an expired
  API token. The token was regenerated by the owner.
- `cargo publish` refreshed the index and rewrote `Cargo.lock`;
  publishing used `--locked` after restoring it.
- Git credentials and the GitHub CLI were logged in as different
  accounts; pushing worked over SSH, and the pull request was opened by
  the owner.

## Decision

A release is the four-command gate (format, clippy with warnings as
errors, tests, the real-model tests locally), not "it compiles".
