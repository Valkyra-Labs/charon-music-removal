# 01. Audit: the library did not separate anything

2026-09-24. charon-audio 0.1.0 (published 2025-10-05), commit `ba58451`.
Host: Apple M4 Pro, 24 GB, macOS 26.6.

## Context

charon-audio was published a year earlier as a "pure Rust Demucs
replacement" with ONNX, Candle and WASM backends, GPU features and a
README full of capabilities. The owner wanted to know what was real
before building anything on it.

## What was done

A full audit: build every feature combination, run every test, run the
pipeline end to end on a known signal, and check each README claim
against the code.

## Evidence

- The default build failed: `ort = "2.0.0-rc.9"` as a caret
  requirement resolved to rc.13, which changed `SessionBuilder` error
  types; `Cargo.lock` was gitignored. The Candle backend did not build,
  the WASM target had three errors, the no-default-features build failed.
  The README's "Rust 1.70 or later" was false.
- With the build repaired in a scratch copy, the end-to-end run with a
  one-node `Identity` ONNX model "succeeded": four stems, each equal to
  the input to 5.96e-8, a NaN on frame 0 of every stem, and the stems
  summing to 4.0 times the mix. Any valid ONNX file "worked".
- 19 unit tests existed; none ran a model, read or wrote audio, or
  checked separation.
- CI had been deleted rather than fixed, together with its badge.

## What went wrong

The original release shipped a README that described intentions as
features. Nothing in the repository could have caught it: no test ran
a model.

## Decision

Two programmes. Minimum: a status section in the README that tells the
truth, one command that works with a real model, tests in CI, a fixed
manifest, version 0.1.1. Maximum: be measurably better than the
alternatives (faster, same quality, lower memory) and finish the
product. Remove Candle and WASM (placeholders that did not build),
deprecate the unused `performance` module, keep only what is backed by
a test or a measurement.
