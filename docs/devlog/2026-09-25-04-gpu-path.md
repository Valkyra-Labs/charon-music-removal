# 04. The GPU path: own export, STFT in Rust, one CoreML partition

2026-09-25. Host as in 01.

## Context

On CPU Charon was already 2x faster than PyTorch CPU, but PyTorch on
Apple's GPU (MPS) was faster still. The question was whether ONNX
Runtime's CoreML execution provider could run HTDemucs at all.

## What was done

- CoreML failed on the in-graph export in four configurations.
- An own exporter (`tools/export/export_htdemucs.py`) that splits the
  model: the network takes the mix and a complex-as-channels
  spectrogram; Charon computes Demucs's `_spec` and `_ispec` in Rust
  with realfft. The Rust STFT is checked against `torch.stft` fixtures
  at 1e-5 relative.
- CoreML ran the split export, but in 26 partitions: CoreML requires
  convolutions to be 4-D with spatial axes of at most 16384. The
  CoreML-target export rewrites the time branch's 1-D convolutions as
  2-D ones with the time axis tiled into rows with kernel halos
  (exact), and transposed convolutions as zero-stuffing plus
  convolution. 26 partitions became 1.
- ONNX Runtime keys its CoreML cache by model path, so a re-exported
  model loaded a stale compiled program. The cache directory is now
  keyed by the model file's SHA-256.

## Evidence

| step | per-segment time |
|---|---|
| CoreML, 26 partitions | 0.235 s |
| CoreML, 1 partition | 0.157 s |

Parity on the 193 s track: CPU split export 9.2e-4, CoreML 1.3e-5.
Separation only: 16.6 s on CPU (real-time factor 11.6), 5.6 s on CoreML
(34).

Tried and dropped, each measured: WebGPU provider (runs, slower than
CPU), Neural Engine (slower than the GPU), the NeuralNetwork model
format (190 s per run), batch-2 export (slower on both), CoreML
FastPrediction (no change), fp16 conversion (invalid graph).

## What went wrong

- The legacy PyTorch exporter mis-traced a Concat in the tiled graph;
  the CoreML target uses the dynamo exporter (opset 18). Its output is
  structurally but not byte-for-byte reproducible, so verification for
  that file is structural.
- Installing a third-party export package silently downgraded demucs to
  4.0.1; the reference environment was restored and the needed tracer
  patches vendored instead.
- A cold CoreML process spends 7 s (warm macOS cache) to 27 s (cold)
  compiling the model on load. That happens outside ONNX Runtime and
  cannot be fixed from our side.

## Decision

Keep ONNX Runtime and CoreML; pay the compile cost once with a
resident process.
