# UI stack for a cross-platform video and timeline app

2026-09-25. Primary sources: crates.io and GitHub APIs, toolkit
changelogs and source at release tags, wgpu 30 changelog, platform
documentation; the owner's earlier egui app read locally.

## The common problem

No toolkit has a ready widget that shows video decoded natively.
The choice is between a platform player synced to our audio, or
passing GPU textures from the OS decoder into the UI through code we
write per OS.

## Why egui

- One codebase on three OSes, permissive, in Rust with the engine.
- The owner's earlier video app already solved the hard UI patterns in
  egui, with incidents documented: a latest-frame slot read with
  `try_lock` only, a texture updated in place with a generation
  counter, a waveform as a 100-per-second peak envelope, audio
  playback where the output callback owns an atomic cursor fed by a
  lock-free ring, rebuild of a dead audio stream after a device
  change, native menus through muda, dialogs through rfd.
- Accessibility (AccessKit) is on by default; the focus crash that
  made the owner's earlier video app disable it in egui 0.28 is reported fixed by
  0.36.

## What is not reused from the owner's earlier video app

Its decode layer: OpenCV for video and ffmpeg subprocesses for audio,
macOS-specific. The app needs per-OS native decoders (see
`2026-09-25-licensing-codecs-gpu.md`). Also its egui version: 0.28
to 0.36 crosses the 0.32 menu rewrite and the 0.34 `App::ui` change,
so components are ported, not copied.

## Preview does not need 4K

The preview pane is at most about 1280 pixels wide. Decoding with the
OS decoder's hardware scaler to preview size and uploading two NV12
planes (about 1.4 MB per 720p frame) through `queue.write_texture`
with a YUV shader is a copy, but a small one. Zero-copy import is an
optimisation for later, per OS, measured.
